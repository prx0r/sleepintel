# TAGS — content types + mechanisms (v1, 2026-09-26)

Every channel carries `tags[]`. Two families. Feedback resolves per tag:
when pilots return metrics, we learn which TYPES and MECHANISMS hold
people — not just which channels. Tags are the granular layer under verdicts.

## Type tags (production shape)

- type-procedural: do-this-then-this (recipes, assembly, painting, trades-steps)
- type-manual: document read aloud (manuals, terms, specs, rules, standards)
- type-lifecycle: a life, stage by stage (animals)
- type-reference: entry-N-of-M (encyclopaedia, dinosaurs, flags, elements)
- type-trade: a skill per series (electrical → auto)

## Mechanism tags (desire, from MECHANISMS.md)

mech-completionist, mech-place, mech-difficulty, mech-hosted, mech-ritual,
mech-nostalgia, mech-eavesdrop, mech-proportion, mech-suggestion,
mech-collection, mech-curiosity, mech-contrast, mech-rhythm, mech-sensory,
mech-procedural, mech-absurd, mech-linguistic.

## Rules

New channel: ≥1 type tag + ≥1 mechanism tag, or the brief is incomplete.
New tag: three channels sharing an unnamed pattern, or it stays prose.
Tags resolve in ANALYTICS content-feature view.
